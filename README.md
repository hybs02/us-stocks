# 米国株 中長期スクリーナー

S&P500の全銘柄から「いま買う候補」を毎晩自動で選び、スマホで確認できるツール。
数ヶ月〜1年の保有を想定しています。

**スマホ用**: https://hybs02.github.io/us-stocks/

## しくみ

```
GitHub Actions（毎晩・米国市場が閉じたあと）
  └ scan.py が503銘柄を評価して data.json を作る
      └ スマホは data.json を読むだけ
```

このため**APIキーも待ち時間も不要**です。スマホ側は一切計算しません。

## 何を根拠に選んでいるか

20年・503銘柄の実データで検証し、**実際に効いた要因だけ**を使っています。
毎月ランク付けして上位20%と下位20%の後のリターンを比べた結果:

| 要因 | 6ヶ月後の差 | t値 | 採否 |
|---|---|---|---|
| 6ヶ月モメンタム | +2.86% | 3.70 | ✅ 採用（重み50%） |
| 長期トレンド（200日線からの乖離） | +2.40% | 2.89 | ✅ 採用（重み30%） |
| 12-1モメンタム | +1.72% | 1.91 | ✅ 採用（重み20%） |
| 低ボラティリティ | −8.16% | −8.40 | ❌ 不採用（下記） |
| 短期リバーサル（逆張り） | −1.45% | −1.90 | ❌ 不採用 |

t値2以上で統計的に有意。

**不採用の理由**
- **短期リバーサル**: FXツールで使っている逆張りは、米国株の中長期では
  マイナスでした。同じ手法を横展開しなくて正解だった、という検証結果です。
- **低ボラ**: 強い負の値が出ましたが、これは学術的な定説と真逆です。
  現在のS&P500構成銘柄で測った生存バイアス（＝生き残った高ボラ銘柄が
  有利に出る）の疑いが濃いため、「高ボラを買う」とは解釈せず、
  **要因ごと使わない**判断にしました。

### 分散のルール

同じ業種に偏ると一緒に下がるため上限を設けています。

| ルール | 年率 | 最大下落 |
|---|---|---|
| 制限なし | +47.6% | −30.5% |
| 大分類5まで | +46.2% | −30.5% |
| **大分類5＋細分類2まで（採用）** | **+46.7%** | **−30.5%** |

細分類の制限を入れても成績は落ちず、分散だけが改善しました
（例: 上位がメモリ関連5銘柄→半導体・医療・エネルギーに分散）。

## ⚠ 数字の見方（重要）

上の年率・最大下落は**実際より良く出ています**。銘柄リストが「現在の」
S&P500だからです（＝過去に脱落した企業が含まれない生存バイアス）。
実際、2008年の暴落がこの検証では−23.9%ですが、現実のS&P500は約−55%でした。

**要因の有効性（順位付けが効くこと）は確認済みですが、示された利益率を
そのまま期待しないでください。**

## ファンダメンタルズの扱い

ROE・利益率・負債などは「**地雷を避けるフィルタ**」としてのみ使い、
順位付けには使っていません。過去の一時点データが取れず、厳密な検証が
できないためです（現在の財務で過去を測ると先読みバイアスになる）。

弾く条件: 営業赤字 / ROEマイナス / D/E>300% / PER>100倍

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | スマホ画面（data.jsonを読むだけ） |
| `scan.py` | 毎晩の評価。GitHub Actionsが実行 |
| `sp500.csv` | 対象銘柄リスト |
| `data.json` | 自動生成される結果 |
| `.github/workflows/daily.yml` | 毎晩の自動実行設定 |

## 手動で更新する

GitHubの Actions タブ →「daily-scan」→ Run workflow
